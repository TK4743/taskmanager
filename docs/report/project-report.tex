\begin{center}
    {\Large \textbf{Abstract}}
\end{center}
\vspace{0.5cm}

Higher education institutions face persistent operational friction in tracking academic deliverables, monitoring extracurricular competitive coding habits, and administering tamper-proof programming evaluations. This report details the systems architecture of \textbf{VSBEC IT Vault} (\texttt{Taskmanager}), an institutional enterprise platform engineered specifically for the Department of Information Technology at V.S.B. Engineering College, Karur. 

The platform orchestrates daily academic task compliance for \textbf{365+ undergraduate engineers} across six departmental cohorts. It eliminates manual spreadsheet logging through an automated 3-tier hierarchical verification state machine (Peer Coordinator $\rightarrow$ Faculty Advisor $\rightarrow$ Head of Department), an autonomous background polling daemon tracking LeetCode GraphQL velocity and GitHub REST commit streaks, and an isolated multi-language programming sandbox supporting C, C++, Java 17, and Python 3. Deployed in departmental production on Vercel with a PostgreSQL relational core, the system guarantees sub-120ms p95 API response times, achieves 100\% paperless deliverable auditing, and provides corporate placement coordinators with tamper-proof student competency dossiers.

\vspace{0.8cm}
\noindent \textbf{Keywords:} Institutional Task Governance, LeetCode GraphQL Sync, Sandboxed Code Execution, RBAC, Academic Enterprise Systems, PostgreSQL.

\chapter{Problem Context \& Engineering Motivation}

\section{Systemic Academic Governance Bottlenecks}
In collegiate engineering environments, managing student laboratory submissions, project milestones, and programming homework via informal channels (e.g., messaging groups, shared spreadsheets, physical record books) leads to severe administrative failure modes:
\begin{enumerate}[nosep]
    \item \textbf{Deliverable Fragmentation:} Academic assignments scattered across personal cloud storage links frequently suffer from expired permissions, preventing faculty auditing.
    \item \textbf{Competitive Coding Visibility Deficits:} Students solve algorithmic problems across external platforms like LeetCode and GitHub; however, mentors lack real-time telemetric visibility into daily streak adherence and topic mastery.
    \item \textbf{Evaluation Latency:} Manual review creates multi-week backlogs, denying students rapid feedback loops during placement preparation seasons.
    \item \textbf{Proctoring \& Evaluation Inconsistency:} Non-sandboxed code reviews fail to assess computational resource limits (CPU runtime and memory bounds), while subjective grading creates variance across section evaluators.
\end{enumerate}

\section{The VSBEC IT Vault Paradigm}
To resolve these institutional bottlenecks, \textbf{VSBEC IT Vault} unifies task governance, competitive telemetry, and secure assessments into a cohesive, role-segregated operational infrastructure. The platform serves as the single source of truth for all curricular and technical evaluations within the Department of Information Technology.

\chapter{Competitive Telemetry \& Background Daemons}

\section{LeetCode GraphQL Integration Engine}
To encourage algorithmic consistency, the platform implements an autonomous polling daemon handled by \texttt{codingTelemetryService.ts}. The service queries the official LeetCode GraphQL endpoint at scheduled intervals to extract student competency vectors:
\begin{itemize}[nosep]
    \item \textbf{Total Solved Metrics:} Aggregate counts partitioned across Easy, Medium, and Hard difficulty tiers.
    \item \textbf{Submission Velocity:} Total accepted submissions over rolling 7-day and 30-day time horizons.
    \item \textbf{Daily Streak Adherence:} Boolean verification of whether a student resolved at least one problem during the active diurnal window.
\end{itemize}

\section{GitHub Commit Activity Ingestion}
Parallel to algorithmic metrics, the \texttt{githubSyncService.ts} module interfaces with the GitHub REST API v3. It tracks daily commit counts, repository contribution velocity, and pull request events across linked student developer handles, computing an empirical ``Development Velocity Index''.

\chapter{Sandboxed Multi-Language Compiler Runtime}

\section{Execution Isolation Environment}
The \texttt{codingSandboxService.ts} delivers an isolated execution engine embedded directly within the browser interface via the Monaco Editor. The architecture guarantees deterministic grading through the following constraints:
\begin{itemize}[nosep]
    \item \textbf{Supported Runtimes:} C (GCC 12), C++ (G++ 12), Java 17 LTS, and Python 3.11.
    \item \textbf{Resource Caps:} Strict 2.0-second wall-clock CPU execution timeout and 256MB resident set size (RSS) memory ceiling.
    \item \textbf{Test Case Verification:} Standard input (\texttt{stdin}) injection against both public sample tests and obfuscated hidden test suites.
\end{itemize}

\begin{lstlisting}[language=SQL,caption={Normalized Relational Schema for Sandboxed Assessment Runs.}]
CREATE TABLE coding_submissions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    student_id UUID REFERENCES users(id) ON DELETE CASCADE,
    challenge_id UUID REFERENCES coding_challenges(id),
    language VARCHAR(32) NOT NULL,
    source_code TEXT NOT NULL,
    test_cases_passed INTEGER NOT NULL,
    total_test_cases INTEGER NOT NULL,
    execution_time_ms INTEGER NOT NULL,
    memory_used_kb INTEGER NOT NULL,
    status VARCHAR(32) NOT NULL, -- 'ACCEPTED', 'TIME_LIMIT_EXCEEDED', 'WRONG_ANSWER'
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
\end{lstlisting}

\chapter{Conclusion \& Strategic Roadmap}

\section{Conclusion}
VSBEC IT Vault proves that academic administrative workflows and competitive technical benchmarking can be successfully synthesized into a unified, secure enterprise system. By replacing manual record-keeping with automated daemons and hierarchical verification, the platform elevates academic rigor and accelerates placement readiness for the undergraduate engineering cohort.
